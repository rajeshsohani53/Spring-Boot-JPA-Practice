# Spring Boot + JPA — Student REST API (Phase 2)

A database-backed upgrade of my earlier [in-memory REST API practice project](https://github.com/rajeshsohani53/Spring-Boot-API-Building-Practice) — rebuilt with **Spring Data JPA** and **MySQL**, so data now persists across restarts, plus a connected HTML/JavaScript frontend for full CRUD.

---

## What this project does

A Student Management REST API backed by a real MySQL database. From the browser you can:

- **Create** a student
- **Read** all students, or one student by id
- **Update** a student's details
- **Delete** a student

Unlike the Phase 1 version, data is stored in **MySQL**, so it survives an application restart.

---

## Tech stack

- **Java 17**
- **Spring Boot 3.x** — Spring Web, Spring Data JPA
- **Hibernate** (JPA implementation, used under the hood)
- **MySQL** — persistent storage
- **Maven** (build tool)
- **HTML + vanilla JavaScript** (`fetch` API) — frontend for CRUD

---

## API endpoints

| Operation | Method | URL | Body |
|-----------|--------|-----|------|
| Create | POST | `/students` | `{ "name": "...", "course": "..." }` |
| Read all | GET | `/students` | — |
| Read one | GET | `/students/{id}` | — |
| Update | PUT | `/students/{id}` | `{ "name": "...", "course": "..." }` |
| Delete | DELETE | `/students/{id}` | — |

> Note: `id` is auto-generated by the database (`@GeneratedValue`) — it's not sent when creating a student.

## Architecture

```
Browser (add.html / list.html)
        |  fetch (JSON over HTTP)
StudentController   (@RestController — handles requests)
        |
StudentRepository   (JpaRepository — free CRUD, no SQL written)
        |
Hibernate           (generates and runs the SQL)
        |
MySQL (studentdb)   (persistent storage)
```

- `Student` is a JPA `@Entity` — one object maps to one row in the `student` table.
- `StudentRepository` is an empty interface extending `JpaRepository<Student, Integer>` — `save()`, `findAll()`, `findById()`, and `deleteById()` come for free.
- The controller is injected with the repository via `@Autowired` (dependency injection) and never manages storage itself.

## How to run

1. Have **Java 17+** and a running **MySQL server** installed.
2. Create the database:
   ```sql
   CREATE DATABASE studentdb;
   ```
3. In `src/main/resources/application.properties`, set your own MySQL username/password.
4. Open the project in your IDE as a Maven project and run the main application class.
5. On startup, Hibernate automatically creates the `student` table — no manual `CREATE TABLE` needed.
6. Open in your browser:
   - Add a student: `http://localhost:8080/add.html`
   - View / update / delete students: `http://localhost:8080/list.html`

To test the API directly:
```
curl -X POST http://localhost:8080/students -H "Content-Type: application/json" -d "{\"name\":\"Raj\",\"course\":\"Java Full Stack\"}"
curl http://localhost:8080/students
```

## What I learned

- **JPA vs Hibernate vs Spring Data JPA** — JPA is the specification, Hibernate is the implementation that generates and runs SQL, and Spring Data JPA sits on top and removes boilerplate.
- **ORM (Object-Relational Mapping)** — mapping Java objects to database tables automatically instead of hand-writing JDBC/DAO translation code.
- **`@Entity`, `@Id`, `@GeneratedValue`** — mapping a class to a table with an auto-generated primary key.
- **`JpaRepository`** — how an empty interface provides full CRUD, and how `save()` does both insert and update depending on whether the id exists.
- **`@Autowired` and Dependency Injection** — letting Spring provide and manage objects instead of creating them with `new`.
- **`Optional<T>`** — Java's safer way of handling a value that might not exist (`findById(id).orElse(null)`).
- Connecting a plain HTML/JS frontend to a persistent backend, and confirming real persistence by restarting the app and seeing data survive.

Detailed, step-by-step concept notes (written while learning) are in the notes file in this repo.
